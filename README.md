# VeritasHR: One Employee, One Truth
**Find, explain and rank inconsistencies in employee data across HR systems, and see the impact of each fix before anyone approves it.**
Emirates Group HR Data Quality Challenge (Ignyte).

- Onboards **any extra HR system** dropped in the folder (linked to Core HR and compared field by field), not just the four in the brief.
- Reads HR extracts **as they are**: file names, column names, delimiters, date formats, status words and ID formats are worked out automatically, and the steward can review every decision.
- Links each employee across Core HR, Payroll, Learning and Access Directory, even when IDs are missing or written differently.
- Finds 10 families of issues and explains each one, with evidence and a suggested value **and the reason for it**.
- Ranks issues by money at risk, security exposure and regulatory reports affected; shows the downstream feeds and reports each fix touches, read from `dependencies.md`.
- Gives a trust score per report and per field, plus a question box that shows how it read the question and which source it used.
- **A named person approves every fix.** Decisions go into a tamper-evident audit log. Nothing is ever written back to source systems.

See [docs/solution_note.md](docs/solution_note.md) ([2-page visual PDF](docs/solution_note.pdf)) for the executive write-up and [watch the Demo Video on Google Drive (2m49s)](https://drive.google.com/file/d/1hzVHcrQZQMo0llZqvo7oXy2aoaLHLOqJ/view?usp=sharing) ([GitHub mirror](docs/demo_video.mp4)).
Scored issue list is available at [`submission/issue_list.csv`](submission/issue_list.csv).

## Quick start
```bash
git clone https://github.com/PegBitStudio/veritashr.git
cd veritashr
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

python -m src.pipeline           # writes submission/issue_list.csv
streamlit run ui/app.py          # dashboard at http://localhost:8501
python -m pytest -q              # 34 tests
```
Python 3.10+ (tested on 3.10, 3.12 and 3.14). The engine uses only the standard library.

### Docker (offline, non-root)
```bash
docker build -t veritashr .
docker run -p 8501:8501 -v /path/to/extracts:/data:ro -v veritas-audit:/audit veritashr
```

## Submission day: running on the official test set
1. Put the organisers' files (any names, CSV/Excel/JSON, plus `data_dictionary.md` and `dependencies.md`) in a new folder, e.g. `data/official/`.
2. Run:
   ```bash
   python -m src.pipeline --data data/official --out submission/issue_list.csv
   ```
3. Check the console output:
   - **auto-mapped columns**: every important field should be mapped. If one is wrong, pin it in `data/official/schema_mapping.json` (see below) and run again.
   - **Records matching no Core HR employee**: a large number usually means the ID column was mis-mapped.
4. Open the dashboard on the same data and spot-check the top 20 issues:
   ```bash
   set VERITAS_DATA_DIR=data/official      # macOS/Linux: export VERITAS_DATA_DIR=data/official
   streamlit run ui/app.py
   ```
5. Submit `submission/issue_list.csv`. It is ranked (`priority_rank`), with `suggested_fix`, `recommended_target_value`, `confidence_score`, `evidence`, `rationale`, `affected_reports` and `downstream_impact`.

### Pinning a mapping (`schema_mapping.json` in the data folder)
```json
{
  "payroll": {"file": "PAY_EXTRACT_2026.csv", "columns": {"employee_ref": "Staff Number", "bank_iban": "Acct"}},
  "core_hr": {"columns": {"employment_status": "Emp Status"}}
}
```
Canonical field names are listed in `src/ingestion/schema_mapper.py` (`CANONICAL_SCHEMAS`).

## How we tested without the official data
| Test | Command | Result |
|---|---|---|
| Synthetic pack, 255 planted errors | `python -m src.pipeline` | 255/255 found, 1 extra flag (F1 99.8%) |
| Scrambled copy (renamed files and columns, `;` delimiter, new date and status formats, 10% of payroll IDs removed) | `python scripts/make_messy_variant.py` then `python -m src.pipeline --data data/variants/messy` | Same result |
| Blind test: 80 errors of 10 types the tool was not built against | `python scripts/inject_blind_errors.py` | 80/80 found |
| A 5th, unseen system (time-attendance file) dropped in the folder | `pytest tests/test_extra_source.py` | 13/13 found, 0 false alarms |

The synthetic pack and its answer key are generated by `scripts/generate_mock_dataset.py`. Scores on the official test set will differ.

## Issue families
| Family | Examples |
|---|---|
| Ghost / orphan records | Left in Core HR but still paid; payee or account with no Core HR employee |
| Security exposure | Leaver with an active directory account; one person with several accounts |
| Cross-system conflicts | Department vs payroll cost centre or LMS; job title vs LMS role; same ID with a different name; active in HR but stopped in payroll |
| Invalid codes / formats | Department, grade, location, status, IBAN, Emirates ID |
| Dates | Payroll start vs hire date; exit before hire; future dates; leaver with no exit date |
| Missing values | Mandatory Core HR fields; IBAN or salary on active payroll; active employee missing from payroll |
| Duplicates | Same Emirates ID; same DOB and name; fuzzy name twins; two active payroll records |
| Out of date | Active staff with expired mandatory or safety training |

## Repository layout
```
src/ingestion/   loader.py (files, data dictionary, lineage), schema_mapper.py (auto-mapping)
src/matching/    record_linker.py (two-pass ID + name matching)
src/anomaly/     detector.py, extended_checks.py
src/impact/      blast_radius.py (feeds and reports touched by a fix)
src/trust/       calculator.py (report / field / system trust)
src/qa/          query_box.py ("Ask HR Truth")
src/governance/  audit_log.py (hash-chained decisions, change-set export)
ui/app.py        Streamlit dashboard (steward / analytics lead / systems owner)
scripts/         mock data, scrambled-variant and blind-error generators
tests/           34 automated tests
```

## Responsible AI
Human approval of every fix · named reviewer, reason required to reject · hash-chained audit log · no write-back to source systems · deterministic, explainable rules · runs offline with no external AI services · personal identifiers masked on screen by default.
